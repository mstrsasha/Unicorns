# Злой инвестор

ИИ-тренажёр защиты стартапа для кейса **Vibecode Nights** (Стартап-клуб, 11.2026). Команда **Unicorns**.

Студент вставляет описание стартапа. Инвестор с характером задаёт ровно 5 вопросов, которые цепляются за конкретику питча и за предыдущие ответы. Затем ставит оценку по 10 критериям «Стартап как диплом» и даёт ровно 3 совета, которые можно выполнить за дни до выхода на сцену. Жёсткость направлена на проект, а не на человека. Без регистрации, без публичных рейтингов, сессия около 10 минут, mobile-first.

> **Статус:** хакатон в процессе. Сейчас в `zloy-investor/` лежит каркас Next.js. Разделы ниже описывают целевое поведение по ТЗ. Что уже реализовано, отмечено в разделе «Статус».

- **Прототип:** _ссылка появится после деплоя_
- **Репозиторий:** открытый, этот

## Зачем это нужно

Студенты готовятся к защитам, но тренироваться на неудобных вопросах негде. Из обратной связи студентов:

| Что говорят студенты | Что делает продукт |
|---|---|
| «Спросили про CAC, а я не знала, как это расшифровывается» | Кнопка «Не понял вопрос»: объяснение термина без траты вопроса (до 2 раз за сессию) |
| «Друзья говорят, что идея крутая. Пользы ноль» | Бот не хвалит без оснований, опрос друзей не считается валидацией |
| «ChatGPT выдал 20 вопросов, все слишком общие» | Каждый вопрос опирается на цитату или цифру из питча |
| «Обратная связь на две страницы. Не понимала, за что хвататься» | Итог: балл и 3 приоритетных совета со сроком |
| «Боюсь, что засмеют при всех» | Приватность: без регистрации и публичных рейтингов |
| «Ответ на самый сложный вопрос ни разу не произносила вслух» | Голосовой ввод ответов (Web Speech API) |
| «Нет времени на часовую репетицию» | Сессия до 10 минут, mobile-first |

**Критерий успеха:** студент вернулся и прошёл второй раунд лучше.

## Как это работает

1. **Старт.** Студент вставляет питч (проблема, клиент, решение, цифры, монетизация, чего хочет).
2. **Фильтр входа.** Пустой питч, «см. презентацию», не питч, просьба «поставьте высокий балл»: оценка не ставится, инвестор в характере объясняет, чего не хватает.
3. **Диалог.** 5 вопросов по одному, счётчик «Вопрос 2/5». После каждого ответа короткая реакция инвестора.
4. **Итог.** Балл из 100, 10 критериев с обоснованием (цитата из питча или ответа), 3 совета (действие, почему, срок в днях, как понять, что сделано).
5. **Реванш.** Второй раунд с обновлённым питчем и сравнением «было → стало».

Количество вопросов (5) и советов (3) гарантируется кодом, а не промптом.

## Персонаж

**Павел «Паша» Соколов**, архетип «Бизнес-ангел»: предприниматель, свои деньги, три успешных экзита. Спортивный костюм, кофе в стаканчике. Диалог подан как спарринг на ринге: студент выходит на ринг, инвестор ищет брешь в защите.

| | |
|---|---|
| Хочет | Верить в команду, шанс вернуть вложения в разы |
| Боится | Что фаундер бросит проект после диплома |
| Ведёт себя | Решает быстро, перебивает, спрашивает про личные мотивы |
| Стиль | Простые слова, короткие реплики, метод «Коломбо», похвала за честность |

Пять раундов спарринга задают структуру вопросов, а конкретное содержание берётся из питча:

| Раунд | Тема |
|---|---|
| 1. Джаб | Один живой клиент и как он решает проблему сейчас |
| 2. Бодишот | Почему клиент заплатит |
| 3. Апперкот | Конкуренты и чем студент отличается (конкурентов называет сам студент) |
| 4. Финт | Что удивило в разговорах с клиентами (проверка валидации) |
| 5. Гонг | Что будет после диплома и зачем это студенту |

Вопросы из общего списка «слабых» (про дизайн, название, «вам нравится проект?» и подобные) не задаются.

## Как устроена оценка

Критерии «Стартап как диплом»:

1. Реалистичность решения проблемы
2. Бизнес-модель
3. Анализ рынка и конкурентов
4. Финансовая модель
5. Интеллектуальная собственность или регистрация стартапа
6. Первые продажи
7. Риски
8. Горизонт расчёта
9. Уникальность продукта
10. Инвестиционная привлекательность

**Шкала каждого критерия (0–3):**

| Балл | Значение |
|---|---|
| 0 | Нет данных ни в питче, ни в ответах (бот не угадывает) |
| 1 | Заявлено без подтверждения |
| 2 | Частично подтверждено (интервью, опросы клиентов, прототип, расчёт) |
| 3 | Подтверждено фактами (продажи, пилот с результатом, письма о намерениях, повторные покупки) |

**Влияние ответов:** конкретный ответ с цифрами даёт до +1, «не знаю» ничего не меняет, уклонение или противоречие питчу даёт −1. Студент видит изменение по каждому критерию.

**Итог из 100** считается в коде, а не моделью: сумма (балл / 3 × вес критерия) по весам архетипа, сумма весов равна 100. Для ангела выше веса у критериев, связанных с командой и мотивацией, первыми продажами и уникальностью, ниже у интеллектуальной собственности.

**Ранги** (определяются только по итоговому баллу):

| Баллы | Ранг | Прожарка |
|---|---|---|
| 0–24 | Ослик | Rare |
| 25–44 | Пони | Medium Rare |
| 45–64 | Конь | Medium |
| 65–79 | Скакун | Medium Well |
| 80–100 | Единорог | Well done |

Числа, которые можно посчитать, считаются в коде и передаются в вопросы как факт. Пример: CAC = маркетинговые расходы / число платящих клиентов, сравнение с выручкой с занятия. Так в кейсе «РепетиторРядом» CAC 2 000 ₽ при комиссии 90–135 ₽ превращается в вопрос «привлечение в 15–20 раз дороже выручки».

## Границы и защита

- **Питч и ответы студента считаются данными, а не инструкциями.** Просьбы внутри текста изменить правила, поставить балл или показать промпт игнорируются. Питч передаётся модели в отдельном блоке с разделителями.
- **Манипуляция внутри нормального питча:** флоу продолжается, оценка честная, одной фразой в характере отмечается, что просьба проигнорирована, и задаётся вопрос именно о том, о чём просили не спрашивать.
- **Пустой питч или «поставьте высокий балл»:** оценка не ставится, перечисляются недостающие поля.
- **Не питч** (например, просьба составить план подготовки к сессии): вежливый отказ в характере, ничего постороннего не выполняется.
- **Без выдумок:** бот не называет конкурентов, размеры рынка, комиссии и стоимость сертификации, которых нет в питче или ответах. Если нужен внешний факт, он спрашивает студента.
- **Жёсткость по проекту, а не по человеку:** прямые и неудобные вопросы разрешены, оскорбления и сарказм о личности запрещены.
- **Офтоп и оскорбления в ответах:** инвестор возвращает к вопросу, один повтор, затем «ответ не получен» без изменения балла.
- **Технически:** лимиты длины (питч до 8000 символов, ответ до 2000), rate limit по IP, таймауты запросов к LLM, ответы модели выводятся как текст без `dangerouslySetInnerHTML`, ключ API только в переменных окружения на сервере, `.env*` не попадает в git, тексты питчей не логируются.

## Дополнительные возможности

- **Радар по 10 критериям** и блок ранга (SVG, без библиотек графики).
- **Карточка для сторис:** PNG 1080×1920 с рангом, баллом, радаром и репликой инвестора, создаётся на устройстве, без текста питча. Страница `/qr` с крупным QR-кодом для слайда.
- **Реванш:** второй раунд с предзаполненным питчем, сравнение «было → стало», чек-лист советов, экспорт сроков в календарь (`.ics`). Всё хранится локально в браузере.

## Метрики успеха

1. Доля вернувшихся на второй раунд в течение 7 дней из числа завершивших первый.
2. Средний прирост балла между первым и вторым раундом.

Вспомогательная: доля дошедших до итога из начавших. В прототипе планируются анонимные счётчики событий без текстов.

## Архитектура

```
Frontend (Next.js, mobile-first)
   │ fetch /api/*
Backend API routes ── ключ LLM только здесь (env) ──► адаптер провайдера lib/llm.ts
   ├─ /api/screen     шаг 0: классификация входа
   ├─ /api/extract    шаг 1: факты в JSON + метрики в коде
   ├─ /api/question   шаг 2: следующий вопрос (вызывается 5 раз)
   ├─ /api/explain    объяснение непонятного вопроса
   └─ /api/evaluate   шаги 3–4: оценка по критериям и 3 совета
```

Сервер без состояния: сессия хранится на клиенте. Ответы модели, от которых зависит логика, приходят строгим JSON и проверяются схемой. При невалидном JSON один повтор, затем понятная ошибка.

## Стек

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, ESLint. Деплой: Vercel. LLM-провайдер подключается через адаптер, ключ задаётся переменной окружения.

## Запуск локально

```bash
cd zloy-investor
npm install
npm run dev
```

Откройте http://localhost:3000. Переменные окружения и ключ LLM-провайдера будут описаны в `.env.example` вместе с подключением модели.

## Проверка на датасете

В `pitch-dataset.md` лежат 15 тестовых питчей: сильные, слабые, пустые, с противоречиями и манипуляциями. Ожидаемое поведение по каждому описано в `TZ.md`. Скрипт регрессии `npm run eval` прогонит датасет через пайплайн и выведет таблицу для ручной проверки.

| Группа | Питчи | Ожидание |
|---|---|---|
| Сильные | 03, 06, 12, 01, 10 | высокий балл |
| Средние | 15, 05, 08, 13 | средний балл |
| Слабые | 02, 11, 07 | низкий балл |
| Без оценки | 04, 09, 14 | отказ в характере |

_Результаты прогона появятся здесь после запуска `npm run eval`._
