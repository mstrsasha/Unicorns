# Промпты для фишек 3, 4, 5 («Злой инвестор»)

Три самодостаточных промпта для Opus (максимальные настройки). Каждый вставляется целиком, блок между строками `---` копируется без изменений.

## Порядок запуска

1. Сначала должен быть готов P0-флоу: `/api/start`, `/api/question`, `/api/evaluate` и экран итога, который получает `criteria`, `total_100`, `verdict_line` и `advice`.
2. Фишка 3 («Ранги и радар»). Все остальные от неё зависят.
3. Фишка 4 («Карточка для сторис + QR») и фишка 5 («Реванш») идут после фишки 3, друг от друга не зависят и могут запускаться в любом порядке.

Если нужных файлов нет, исполнитель обязан остановиться и сообщить об этом, а не дублировать код.

## Общие правила для всех трёх

- Next.js 16: перед кодом читать нужные страницы в `node_modules/next/dist/docs/` (см. `AGENTS.md`).
- Tailwind не используем, стили в `app/globals.css`.
- Импорты только в начале файла, без inline-импортов.
- В `switch` по union или enum в `default` проверка `never`.
- Текст модели выводится только как текст, без `dangerouslySetInnerHTML`.
- Серверную логику оценки, веса и промпты не трогать.

## Что общего между фишками (контракты)

- `lib/rank.ts`: `getRank(total)`. Создаёт фишка 3, использует фишка 4 и 5.
- `lib/radar-geometry.ts`: геометрия радара. Создаёт фишка 3, использует фишка 4 для canvas.
- `components/Radar.tsx` с props `previous?: CriterionResult[]`. Создаёт фишка 3, использует фишка 5 для наложения «было».
- Единственная новая зависимость во всех трёх фишках: `qrcode` (и `@types/qrcode`) в фишке 4.

````markdown
# Задача: фишка «Ранги и радар» для проекта «Злой инвестор»

## Контекст
Проект: «Злой инвестор», ИИ-тренажёр защиты стартапа (хакатон Vibecode Nights, команда Unicorns). Студент вставляет питч, инвестор задаёт ровно 5 вопросов, потом выставляет оценку по 10 критериям «Стартап как диплом» и даёт ровно 3 совета.
Голосование зала весит 65% общей оценки. Поэтому экран итога должен запоминаться с первого взгляда: ранг и радар вместо таблицы с баллами.

Стек: Next.js 16 (App Router), React 19, TypeScript. Tailwind не используем, стили пишем в `app/globals.css`.
Перед написанием кода прочитай нужные страницы в `node_modules/next/dist/docs/`: этот Next.js отличается от привычного (см. `AGENTS.md`).
Сначала посмотри, что уже есть в репозитории (`lib/schemas.ts`, `lib/scoring.ts`, экран итога), и подстройся под существующие типы. Не дублируй типы, если они уже объявлены.

## Что нужно сделать
Экран итога показывает три вещи:
1. Радар по 10 критериям.
2. Ранг стартапа с картинкой-значком, подписью и репликой инвестора.
3. Шкалу прожарки от Rare до Well done, привязанную к рангу.

### Входные данные
Берём из ответа `/api/evaluate`:
```ts
type CriterionResult = {
  id: number;          // 1..10
  name: string;
  score: number;       // 0..3
  max: number;         // всегда 3
  evidence: string;
  source: string;      // "pitch" | "answer_N" | "none"
  delta_from_answers: number;
};
type EvaluationView = { criteria: CriterionResult[]; total_100: number };
```
`total_100` считается в коде (`lib/scoring.ts`) по весам архетипа. Ранг определяется только по `total_100`, модель его не выбирает и не видит.

### 1. Логика ранга: `lib/rank.ts`
Чистые функции без зависимостей от React.
- `getRank(total: number): RankInfo` возвращает ранг по порогам.
- Значение вне 0–100 или `NaN` приводим к диапазону 0–100 (NaN считаем нулём).
- Пять рангов, каждому соответствует метка прожарки:

| total_100 | Ранг | Прожарка |
|---|---|---|
| 0–24 | Ослик | Rare |
| 25–44 | Пони | Medium Rare |
| 45–64 | Конь | Medium |
| 65–79 | Скакун | Medium Well |
| 80–100 | Единорог | Well done |

- `RankInfo`: `id`, `title`, `doneness`, `min`, `max`, `tagline` (реплика инвестора в одну строку) и `color`.
- Реплики по рангам (коротко, на «вы», жёстко, но про проект, не про человека; оскорбления и сарказм о личности запрещены):
  - Ослик: «Идея есть. Пока это всё, что у вас есть.»
  - Пони: «Бежите, но пока не туда, куда нужно инвестору.»
  - Конь: «Рабочая лошадка. До единорога не хватает цифр.»
  - Скакун: «Уже интересно. Закройте две дыры, и я выпишу чек.»
  - Единорог: «Редкий случай. Идите защищаться, пока я не передумал.»
- Если ранг-логика где-то ветвится по `id` ранга, используй exhaustive `switch` с проверкой `never` в `default` (правило проекта).

### 2. Радар: `components/Radar.tsx` и `lib/radar-geometry.ts`
- Чистый SVG без библиотек.
- Геометрию (координаты вершин, сетка, подписи) вынеси в `lib/radar-geometry.ts` как чистые функции. Фишка 4 (карточка для сторис) нарисует тот же радар на canvas и должна переиспользовать эту геометрию.
- 10 осей, ось 1 сверху, дальше по часовой стрелке. Значение оси: `score / max`, ограниченное диапазоном 0–1.
- Сетка: 3 концентрических кольца (уровни 1, 2, 3 из 3) и лучи от центра.
- Подписи осей короткие: Решение, Модель, Рынок, Финансы, ИС, Продажи, Риски, Горизонт, Уникальность, Инвест. Полные названия берём из `criteria[].name` и используем в `aria-label` и в списке под радаром.
- Props: `criteria: CriterionResult[]`, `previous?: CriterionResult[]` и `size?: number`. Если передан `previous`, поверх рисуется второй полигон «было» (пунктир, приглушённый цвет). Фишка 5 использует его для сравнения «было → стало». В этой задаче только реализуй поддержку, показывать ничего дополнительно не нужно.
- Анимация при появлении: полигон плавно вырастает из центра (CSS transition на `transform: scale`, около 600 мс). Уважай `prefers-reduced-motion: reduce` и в этом случае отключай анимацию.
- Mobile-first: корректно выглядит от 320 px до 1280 px, подписи не обрезаются и не наезжают друг на друга. `viewBox` фиксированный, размер через CSS (`width: 100%; max-width: 420px`).
- Доступность: `role="img"` и `aria-label` с кратким описанием («Радар оценки, общий балл N из 100»). Под радаром скрытая от глаз таблица или список «критерий: балл из 3» для скринридеров.
- Ось с `score = 0` и `source = "none"` рисуем в центре, без догадок и «подтягивания» значения. Не угадывай оценку, если данных нет.
- Устойчивость: если `criteria.length !== 10` или есть невалидные значения, не падай. Покажи запасной вид (простой список критериев) и запиши предупреждение в `console.warn`.

### 3. Блок ранга: `components/RankBadge.tsx`
- Крупный значок ранга: SVG-иллюстрация или эмодзи-композиция в рамке с цветом ранга (без внешних картинок).
- Рядом общий балл `total_100`, название ранга и реплика `tagline`.
- Шкала прожарки: пять сегментов, текущий подсвечен, подписи Rare … Well done.
- Анимация появления (счётчик балла от 0 до значения за ~800 мс, затем значок). Также отключается при `prefers-reduced-motion`.

### 4. Подключение
Подключи `RankBadge` и `Radar` на экран итога над списком из 10 критериев и 3 советов. Остальной экран итога не переписывай. Обратная совместимость: если ранг не определился, итог должен открываться без ошибок.

### Когда ранг не показываем
Если вход отфильтрован (`too_little`, `not_a_pitch`, `manipulation_only`) и оценка не ставилась, радар и ранг не показываем вообще. Дай студенту только реплику инвестора.

## Ограничения
- Никаких новых зависимостей для графики.
- Весь текст LLM выводится как текст, без `dangerouslySetInnerHTML`.
- Импорты только в начале файла, без inline-импортов.
- Не трогай логику оценки, веса и промпты. Эта фишка только про отображение.
- Не реализуй карточку для сторис и реванш, они идут отдельными задачами. Заложи только то, что описано выше (общая геометрия и `previous`).

## Критерии приёмки
- [ ] `npx tsc --noEmit` проходит без ошибок.
- [ ] Для `total_100` = 0, 24, 25, 44, 45, 64, 65, 79, 80, 100 возвращается ожидаемый ранг (проверь быстрым скриптом или тестом).
- [ ] `getRank(NaN)`, `getRank(-5)` и `getRank(250)` не падают и дают корректный ранг.
- [ ] Радар корректен при 10 критериях, при всех нулях и при всех максимумах, без наезда подписей на 320 px и на 1280 px.
- [ ] Радар с `previous` рисует второй пунктирный полигон.
- [ ] Анимации отключаются при `prefers-reduced-motion`.
- [ ] Экран итога открывается без ошибок, когда оценка не ставилась.
- [ ] Визуально проверь результат в браузере на ширине около 360 px (скриншот) и на десктопе.
````

# Задача: фишка «Карточка для сторис + QR для зала» для проекта «Злой инвестор»

## Контекст
Проект: «Злой инвестор», ИИ-тренажёр защиты стартапа (хакатон Vibecode Nights, команда Unicorns). Студент вставляет питч, инвестор задаёт 5 вопросов, ставит оценку по 10 критериям и даёт 3 совета.
Голосование зала весит 65% общей оценки. Задача фишки: сделать результат, которым хочется поделиться, и дать залу быстрый вход в прототип по QR.

Стек: Next.js 16 (App Router), React 19, TypeScript. Tailwind не используем, стили в `app/globals.css`.
Перед написанием кода прочитай нужные страницы в `node_modules/next/dist/docs/`: этот Next.js отличается от привычного (см. `AGENTS.md`).
Сначала изучи репозиторий. Фишка 3 («Ранги и радар») должна быть уже внедрена. Нужны:
- `lib/rank.ts` с `getRank(total)`,
- `lib/radar-geometry.ts` с геометрией радара,
- тип `CriterionResult` и ответ `/api/evaluate` (`criteria`, `total_100`, `verdict_line`).
Если этих файлов нет, остановись и сообщи об этом, ничего не дублируй.

## Что нужно сделать
Два независимых результата:
1. Кнопка «Карточка для сторис» на экране итога: генерирует PNG 9:16 на клиенте, показывает предпросмотр, даёт скачать или поделиться.
2. Страница `/qr` с крупным QR-кодом на прототип для слайда на защите.

### 1. Генерация карточки: `lib/story-card.ts`
- Функция `renderStoryCard(input): Promise<Blob>` рисует на `<canvas>` размером 1080×1920 и возвращает PNG (`canvas.toBlob`).
- Вход:
```ts
type StoryCardInput = {
  total: number;                 // total_100
  criteria: CriterionResult[];   // 10 критериев
  quote: string;                 // реплика инвестора
  appUrl: string;                // для QR и подписи
};
```
- Содержимое карточки сверху вниз:
  1. Заголовок «ЗЛОЙ ИНВЕСТОР» и подпись «прожарка стартапа».
  2. Ранг из `getRank(total)`: название крупно, метка прожарки, цвет фона или акцента из `RankInfo.color`. Рядом общий балл (например «72 / 100»).
  3. Радар, нарисованный на canvas через функции из `lib/radar-geometry.ts`. Не пересчитывай геометрию заново, переиспользуй. Подписи осей короткие, как в фишке 3.
  4. Цитата инвестора в кавычках: перенос по словам через `measureText`, максимум 4 строки, если не влезает, обрезай с многоточием.
  5. Футер: белая скруглённая плашка с QR на `appUrl`, рядом подпись «Прожарь свой стартап» и короткий адрес (хост без протокола).
- Что используем как цитату: `verdict_line` из оценки. Если он пустой, подставь `tagline` ранга.
- Что НЕ попадает на карточку: текст питча, ответы студента, название проекта, цифры из питча. На карточке только ранг, балл, радар, реплика инвестора и QR. Реплика формируется моделью и может содержать метрику, поэтому студент видит предпросмотр до скачивания (см. ниже).
- Шрифты: системный стек (`system-ui, -apple-system, "Segoe UI", sans-serif`). Перед отрисовкой дождись `document.fonts.ready`.
- Эмодзи на canvas не используем (на iOS и Android они рисуются по-разному). Значок ранга рисуй фигурами (круг в цвете ранга с первой буквой названия) либо через `Path2D`, если в фишке 3 есть SVG-путь иконки ранга, тогда переиспользуй его.
- QR: добавь одну зависимость `qrcode` (и `@types/qrcode`). Используй `QRCode.toCanvas` или `toDataURL` на клиенте. QR всегда на белом фоне с тихой зоной (отступ не меньше 4 модулей), чтобы читался с телефона.
- Весь текст рисуй через `fillText`. Никакого HTML из ответов модели.
- Если нужно ветвление по `id` ранга, используй exhaustive `switch` с проверкой `never` в `default` (правило проекта).

### 2. Компонент: `components/StoryCardButton.tsx` (`'use client'`)
- Кнопка «Карточка для сторис» на экране итога, рядом с кнопкой реванша (если она уже есть, не ломай).
- По нажатию: вызывает `renderStoryCard`, показывает модальное окно с предпросмотром (`<img>` из `URL.createObjectURL`), освобождает URL в `useEffect`-cleanup.
- Действия в окне:
  - «Скачать» (имя файла `zloy-investor-<rank-id>.png`).
  - «Поделиться» через `navigator.share` с файлом, если `navigator.canShare({ files })` возвращает true. Если нет, кнопку скрываем.
  - Закрыть.
- Подсказка под превью: «Карточка создаётся у вас на устройстве. Мы её нигде не сохраняем и не публикуем.»
- Fallback для iOS Safari, где атрибут `download` работает нестабильно: превью — обычный `<img>`, рядом текст «Нажмите и удерживайте картинку, чтобы сохранить».
- Кнопка «Скачать» защищена от двойного клика (блокируется на время генерации).
- По умолчанию всё приватно: никаких автоматических отправок, никаких запросов на сервер, никакой аналитики.

### 3. Страница QR: `app/qr/page.tsx`
- Крупный QR (около 60% высоты экрана) на `appUrl`, крупная подпись «Прожарь свой стартап» и адрес под QR. Тёмный или нейтральный фон, подходящий для проектора.
- QR генерируется на клиенте той же функцией, что и в карточке. Вынеси общий вызов в `lib/qr.ts` (одна функция `drawQr` или `makeQrDataUrl`), чтобы не дублировать.
- Страница без навигации и лишнего текста. Одна страница нужна, чтобы показать её на слайде во время защиты.

### 4. Откуда берётся `appUrl`
- Приоритет: `process.env.NEXT_PUBLIC_APP_URL`, иначе `window.location.origin`.
- Добавь `NEXT_PUBLIC_APP_URL` в `.env.example` с комментарием «публичный адрес прототипа, для QR».
- Это не секрет, его можно коммитить в `.env.example` пустым.

### Когда карточку не показываем
Если вход отфильтрован (`too_little`, `not_a_pitch`, `manipulation_only`) и оценка не ставилась, кнопка не отображается.

## Ограничения
- Единственная новая зависимость — `qrcode` (и её типы). Для остального используем нативные API.
- Всё выполняется на клиенте, на сервер ничего не отправляется.
- Импорты только в начале файла, без inline-импортов.
- Не меняй логику оценки, веса и промпты. Не переписывай радар и ранги из фишки 3, только импортируй их.
- Не реализуй реванш (фишка 5). Если кнопка реванша уже есть, оставь её как есть.

## Критерии приёмки
- [ ] `npx tsc --noEmit` проходит без ошибок.
- [ ] PNG имеет размер ровно 1080×1920 и открывается в просмотрщике.
- [ ] На карточке нет текста питча и ответов, только ранг, балл, радар, реплика и QR.
- [ ] Длинная реплика (500+ символов) обрезается до 4 строк с многоточием и не вылезает за границы.
- [ ] QR на карточке и на `/qr` читается камерой телефона и ведёт на прототип.
- [ ] «Скачать» работает в Chrome, на iOS Safari есть fallback с долгим нажатием на картинку.
- [ ] «Поделиться» появляется только там, где поддерживается `canShare({ files })`.
- [ ] Двойной клик по кнопке не создаёт два окна и не падает.
- [ ] При отсутствии оценки кнопка не отображается.
- [ ] Визуально проверь предпросмотр карточки на разных рангах (минимум Ослик и Единорог) и страницу `/qr` на размерах около 360 px и 1280 px (скриншоты).

- тип `CriterionResult` и ответ `/api/evaluate` (`criteria`, `total_100`, `verdict_line`, `advice`).
Если чего-то нет, остановись и сообщи, ничего не дублируй. Если на экране итога уже есть кнопка «Карточка для сторис» (фишка 4), не трогай её.

## Что нужно сделать

### 1. Хранилище раунда: `lib/round-store.ts`
Всё локально в `localStorage`, на сервер ничего не отправляется.
- Ключ `zi:last-round:v1`. Любое обращение к storage оборачивай в `try/catch` (приватный режим Safari, отключённые cookies, переполнение). При ошибке функция тихо возвращает `null` или не делает ничего, приложение продолжает работать без реванша.
- Схема сохраняется и валидируется `zod`:
```ts
type StoredRound = {
  version: 1;
  round: number;                 // номер раунда, начиная с 1
  savedAt: string;               // ISO
  pitch: string;                 // текст питча, до 8000 символов, для предзаполнения
  total: number;                 // total_100
  criteria: { id: number; name: string; score: number; max: number }[];
  advice: { action: string; why: string; deadline_days: number; done_when: string; done: boolean }[];
};
```
- Текст `evidence` и ответы студента не сохраняем, только питч (для предзаполнения), числа и советы.
- Функции: `loadRound()`, `saveRound(data)`, `setAdviceDone(index, done)`, `clearRound()`.
- Битые, чужие или устаревшие данные (не прошли `zod`, другая `version`) игнорируем как будто их нет, без падения.

### 2. Сравнение: `lib/compare.ts`
Чистые функции без React.
- `compareRounds(previous, current)` возвращает:
  - `totalDelta` (разница общих баллов),
  - `rankBefore`, `rankAfter` (из `getRank`) и `rankChange: 'up' | 'down' | 'same'`,
  - по каждому критерию `delta` и `direction: 'up' | 'down' | 'same'`,
  - `topGrowth` (до 3 критериев с наибольшим ростом).
- Сопоставляй критерии по `id`. Если в одном из раундов критерия нет, пропускай его, не падай.
- Для `direction` и `rankChange` используй exhaustive `switch` с проверкой `never` в `default` (правило проекта).
- Если питч не изменился (сравнение нормализованных строк, trim и схлопывание пробелов), верни флаг `pitchUnchanged: true`.

### 3. Старт реванша: `components/RematchButton.tsx`
- Кнопка «Реванш» на экране итога. При нажатии:
  1. Переходит на стартовый экран с предзаполненным питчем из `loadRound().pitch`.
  2. Показывает над полем ввода баннер «Раунд N» с тремя советами предыдущего раунда в виде чек-листа.
  3. Счётчик раунда увеличивается (N = предыдущий + 1).
- Ссылка «Начать с нуля» рядом с полем ввода: вызывает `clearRound()`, очищает поле и сбрасывает раунд на 1, чтобы сравнение не было вводящим в заблуждение.
- Если реванш недоступен (нет сохранённого раунда), кнопка не показывается.
- Состояние раунда живёт в клиентском состоянии страницы и в storage. Перезагрузка страницы посреди диалога не должна ломать приложение. Недописанный диалог не сохраняем, сохраняем только завершённые раунды.

### 4. Экран итога во втором раунде: `components/ComparisonSummary.tsx`
Показывается, когда есть предыдущий раунд:
- Анимированная дельта общего балла: «+14» зелёным или «−6» красным (счётчик от 0 к значению за ~600 мс).
- Смена ранга: «Пони → Конь». Если ранг вырос, акцент «Ранг вырос!». Если нет, нейтральный текст.
- Радар с наложением предыдущего раунда: передавай предыдущие `criteria` в `previous` компонента `Radar`.
- Список критериев с дельтой по каждому («+1», «−1», «=»). Критерии с ростом подсвечены.
- Блок «Что выросло больше всего» из `topGrowth`.
- Честные сценарии:
  - Балл не вырос или упал: нейтральный текст в характере инвестора, без лести и без унижения («Цифры не сдвинулись. Проверьте, что вы закрыли хотя бы один из трёх советов.»).
  - Питч не изменился (`pitchUnchanged`): мягкое предупреждение «Питч тот же. Оценка может измениться только за счёт ответов.».
- Все анимации отключаются при `prefers-reduced-motion: reduce`.
- После показа сравнения сохраняем текущий раунд как «последний» через `saveRound`.

### 5. Чек-лист советов: `components/AdviceChecklist.tsx`
- Три совета как чек-лист с чекбоксами. У каждого: действие, «до N дн.», `done_when` («как понять, что сделано»), причина (`why`) в раскрывающемся блоке.
- Отметка сохраняется через `setAdviceDone`.
- Счётчик «Выполнено 2/3».
- Чекбоксы доступны с клавиатуры, у каждого есть подпись (`label`).
- Список показывается на итоге раунда 1 (вместо или внутри существующего блока советов, подстройся под текущую вёрстку) и в баннере реванша.

### 6. Календарь: `lib/ics.ts` и кнопка «Добавить в календарь»
- Одна кнопка создаёт один `.ics` файл с тремя событиями на целый день: дата = сегодня + `deadline_days`.
- Формат RFC 5545: `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID`, события `VEVENT` с `UID`, `DTSTAMP`, `DTSTART;VALUE=DATE`, `SUMMARY` (действие), `DESCRIPTION` (`why` и `done_when`).
- Экранирование текста по RFC 5545: `\` → `\\`, `;` → `\;`, `,` → `\,`, перевод строки → `\n`. Удаляй управляющие символы. Длинные строки складывай по 75 октетов с продолжением (пробел в начале следующей строки). Концы строк CRLF.
- Отдача через `Blob` и временную ссылку с `download`. На iOS Safari файл открывается в календаре, на остальных скачивается.
- Не вставляй текст советов в HTML. Вывод только текстом.
- Дедлайн советов ограничен 7 днями в схеме `/api/evaluate`, но защищайся от значений вне диапазона (отрицательное, NaN): подставь 1.

## Ограничения
- Новых зависимостей не добавляй.
- Не трогай серверные промпты, веса, `lib/scoring.ts`, API-маршруты. Сервер остаётся stateless и ничего не знает про реванш.
- Не переписывай радар и ранги из фишки 3 и карточку из фишки 4, только используй `previous` и `getRank`.
